# pocketcontext-core

Shared Go library of the PocketContext family (PocketContext Atlas, PocketContext Crew and derived applications): the one-binary server, private local management, tunnel, OAuth/MCP boundary and sync-safe database handling. Read `README.md` and the package you are changing first.

- **Inclusion rule.** Code enters this module only when more than one application uses it and it carries no product behaviour once its parameters are extracted. Anything a single product decides (public routes, read routes, collection names, tool names, copy) is passed in, never written here.
- **No identity defaults.** `appidentity.Identity`, `appserver.Config` and policies are required, validated and never defaulted. Do not add a default value that could be any application. Non-test code never names a product; `python3 tools/identity_scan.py` enforces it. Do not rename fields' meaning across releases without an explicit migration in each application.
- **Security invariants.** Authentication stays on. The local key file is mode 0600 inside the private per-project cache, removed at shutdown, returned by no route and stripped from every public request (`LocalKeyHeader` comes from the identity). Public listeners allow only the product's `Policy.PublicRoute` (fixed OAuth/OTP/`/up` handling aside), with exact Host/Origin and path canonicalization; a missing or empty policy denies. Local management routes are never public, and a public peer on loopback gains no local privilege. The tunnel stays a single project-port proxy; never widen it (no other ports, UDP, exit nodes or forwarding through the server). Keep the frozen negative route set in `appserver/routepolicytest`.
- **Database safety.** The server never opens the synced database directly. Copy in on start, write back through consistent snapshots and atomic renames, and preserve both sides on conflicts through explicit `recover`.
- **Compatibility.** `/api/bundle/instance`, the socket path, `server.lock`, `tunnel.json`, `local.key` and the cache layout are consumed by running older servers and clients. Treat them as a format, and keep `LegacyAppIDs` semantics: diagnose and stop, never adopt.
- **Windows is supported.** Use `filepath`, `sqliteuri.File` for SQLite URIs, platform files for locks and process creation, and `atomicfile.RenameRetry` for renames.
- **Tags and CI.** `build-tags.txt` stays in step with the tailcat release in `go.mod` (`python3 tools/build_tags_sync.py`, and `TestBuildTagsFollowTailcat`). Run before committing: `CGO_ENABLED=1 go test -tags "$(cat build-tags.txt)" ./...`, `python3 tools/name_check.py`, `python3 tools/identity_scan.py`. Local Go must be 1.27.3 (set `GOTOOLCHAIN=go1.27.3` when the system Go is older).
- Use only synthetic test data. Never commit secrets, databases or machine-specific paths: this repository is public.
- Vendored server provenance: `VENDORED.md`. Review upstream security fixes for those packages and port them by hand.
